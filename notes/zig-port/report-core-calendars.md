## API for the date formatting worker

Import `hereabouts.core.calendars` (root: `zig/src/core/systems/calendars/calendars.zig`).
Dates are immutable plain values; operations take `*const CalendarDate` and return new values.
`CalendarDate` contains a `*const CalendarSystem`, `[25]f64` fields, `DateZoneInfo`, and `firstDay`/`minDays`.
`DateField` exposes the TypeScript field indices. Calendar types and period fields are enums with `fromString`.

- `calendarSystem(CalendarType)` selects the Gregorian (`gregory`), ISO-8601, Buddhist, Japanese or Persian rules; the five `*Calendar` constants expose those records directly.
- `dateFromUnixEpoch(calendar, epoch: i64, zoneId, firstDay, minDays)` constructs a date; every `*DateFromUnixEpoch` calendar-specific wrapper is also exported.
- `dateFromFields(calendar, CalendarDateFields, firstDay, minDays)` and the five `*DateFromFields` wrappers return `Error!CalendarDate`. Fields are optional integers, with optional `zoneId`; missing fields follow each calendar's defaults.
- `isGregorianDate`, `isISO8601Date`, `isBuddhistDate`, `isJapaneseDate`, `isPersianDate` inspect the calendar; Gregorian includes the Gregorian-derived calendars, matching TypeScript.
- `dateType`, `dateUnixEpoch`, `dateFirstDayOfWeek`, `dateMinDaysInFirstWeek`, `dateJulianDay`, `dateModifiedJulianDay` expose identity, instant and week rules.
- Era/year/month/day accessors retain their TypeScript `date*` names, including extended/related years, week-years, ISO weeks, week of month, ordinal weekday, day of year and weekday occurrence in month.
- Time accessors retain the `date*` names for AM, hour, hour of day, minute, second, milliseconds and milliseconds in day; leap-year, DST, zone, stable-id, metazone and offset accessors are exported.
- `dateFields`, `dateCompare`, `dateFieldOfVisualDifference` return field records, ordering and an optional pattern character respectively.
- `dateToString`, `dateToDateString`, `dateToTimeString`, `dateToDateTimeString`, `dateToISOString`, `dateToLocalISOString` take an allocator first and return caller-owned strings. `TimeStringOptions` matches TypeScript.
- `writeString`, `writeDateString`, `writeTimeString`, `writeDateTimeString`, `writeISOString` take a `*std.Io.Writer`; the last takes a Boolean selecting UTC versus local ISO output.
- `dateSet`, `dateWithZone`, `dateStartOf`, `dateEndOf` return dates. The bounds use `CalendarDateModField`.
- `timePeriod()` returns zeroed `TimePeriod`; its eight fields are `f64` with `get`/`set` helpers, and `TIME_PERIOD_FIELDS` preserves TypeScript order.
- `dateAdd`, `dateSubtract` return `Error!CalendarDate`; fractional period components truncate as in TypeScript.
- `dateUntil`, `dateSince`, `dateDifference`, `dateDifferenceSigned` return `TimePeriod`; `DateDiffOptions` has `includeWeeks`, optional field slice, and `rollupFractional`.
- `dateRelativeTime(date, other, optionalField, options)` returns `{ field, value }`.
- `zoneInfoFromUTC`, `currentMetazone`, `getStableTimeZoneId`, `substituteZoneAlias` expose zone helpers. Default-database zone strings are static; replacement-database strings borrow that database.
- `hereabouts.core.zoneutil.getTZC(offsetMs: i64)` returns `{ offset: f64, negative, hours, minutes }`, equivalent to the TypeScript tuple.

## Implementation and intentional differences

Internal arithmetic uses doubles, JS signed remainders, int32 wrapping and Math.round semantics.
The metazone, stable-id, alias and Japanese-era tables are generated by
`packages/hereabouts/scripts/zig/core-calendars.ts`; TypeScript remains the data source.
Japanese eras are extracted from its private literal, yielding 237 eras. Integer zero padding is
implemented locally instead of depending on decimal numbering.

Public epoch/field inputs are integer typed, so fractional or non-finite constructor arguments
cannot be expressed. Period components and difference results retain doubles. Missing month/day
in ISO/Japanese constructors produces `InvalidFields`, replacing TypeScript throws/NaN dates;
non-finite arithmetic results produce `InvalidDate`. No JS Date conversion or runtime structural
`isCalendarDate` validator is needed for the typed Zig API.

CalendarSystem month callbacks require valid zero-based month indices: `daysInMonth` returns 0
outside 0..11, and month-table helpers clamp invalid indices instead of TypeScript's out-of-bounds
throws. Tested fractional `monthStart` values use valid adjacent months. `substituteZoneAlias`
uses a string map, so JS Object prototype keys such as `toString` do not reproduce accidental
prototype lookup behavior. Custom locale-schema configurations are not added; stable-id lookup
uses the shipped schema. Replacement timezone databases are supported and tested.

## Preserved TypeScript quirks

- Julian calendar before the 1582 cutover, including cutover-gap construction behavior; Julian-day range clamps and huge-year int32 wrapping.
- Persian negative-year leap calculation uses the signed remainder; Persian field resolution ignores requested `zoneId` and uses the current offset.
- Add/difference operations use Gregorian clamping and YMD helpers even for Persian dates.
- Fractional period truthiness selects the arithmetic path before the components are truncated; `millisToTimePeriod` leaves days zero.
- The last requested difference field controls fractional rollup, including unsorted field lists; fractional minute rollup retains the TypeScript expression multiplying seconds by a minute.
- Same-day fall-DST differences bypass calendar differencing; month-end differences are directional.

Fixed one bug in the inherited Zig code: `utcFromWall` had reconstructed UTC from the resolver's
zone-info offset. In a spring gap that info describes the post-transition zone, while the resolved
UTC instant uses the earlier offset. The wrapper now preserves the resolver's actual adjustment;
13 existing reference cases caught the error.
